# Contract: status transport, server → stylesheet

**Feature**: `020-reconcile-console-design` | **Governing**: `docs/design-constitution.md` §II, §V, §VI

How a server-rendered element gets a status color **without owning a copy of it**.
This is the FR-004a contract: the server emits the status *name*; the stylesheet
owns every color, fill alpha, and border alpha.

---

## 1. Elixir side

`SpeckitOrchestrator.Web.CoreComponents` stops carrying colors.

**Before**

```elixir
@palette %{
  pending: {"Pending", "#64748b"},
  ...
  never_started: {"Never started", "#475569"}
}
def palette, do: @palette                      # {label, hex}
```

**After**

```elixir
@labels %{
  pending: "Pending", blocked: "Blocked", running: "Running",
  escalated: "Escalated", halted: "Halted", failed: "Failed",
  done: "Done", never_started: "Never started"
}

@doc "Human label for a lifecycle status. Prose, not a contract value."
@spec label(atom()) :: String.t()
def label(status), do: Map.get(@labels, status, to_string(status))

@doc """
Canonical contract status name for a lifecycle status, as emitted into markup.
`:never_started` folds to `"blocked"` — the contract status whose meaning it
shares — so no eighth color exists (docs/design-constitution.md §II).
"""
@spec status_class(atom()) :: String.t()
def status_class(:never_started), do: "blocked"
def status_class(status) when status in ~w(done running escalated halted failed pending blocked)a,
  do: to_string(status)
def status_class(_other), do: "pending"

@doc "The seven contract statuses, in the contract's table order."
@spec statuses() :: [String.t()]
def statuses, do: ~w(done running escalated halted failed pending blocked)
```

**Rules**

- `palette/0` is **removed**, not deprecated. Every caller
  (`pipeline_dag_live.ex:283`, `escalations_live.ex:558`) moves to
  `label/1` + `status_class/1`.
- `escalations_live.status_color/1` is **removed** — it is the per-view palette
  copy the spec names.
- `status_class/1` is total: an unrecognised atom folds to `"pending"` rather
  than raising. Rationale: a console is an observability surface and MUST NOT
  crash a view over an unexpected status; the loud-failure obligation of
  Principle II sits on the store and the pure core, not on the renderer. The
  fold is tested.
- No function in `lib/**/web/**` returns, interpolates, or defaults to a color.

## 2. Markup side

Every status-bearing element carries `data-status`:

```heex
<span class="status-chip" data-status={status_class(@status)}>{label(@status)}</span>
<span class="status-dot"  data-status={status_class(@status)}></span>
<div  class="dag-node"    data-status={status_class(@feature.status)}>…</div>
```

**Rules**

- `data-status` is the transport. `class="status-#{...}"` is an acceptable
  alternative where an existing class already discriminates (`.phase-cell-*`,
  `[data-legend-status]`, `[data-phase-state]`); a surface MUST NOT use both for
  the same element.
- No `style=` attribute on any console surface may carry a color, gradient,
  shadow, radius, font, or spacing value. *(FR-004a)*
- **The only permitted inline styles** are the cost gauge's two fill widths:
  `style={"width: #{@committed_fill}%;"}` and `style={"width: #{@fill}%;"}`.
  *(FR-004b)*

### The six inline styles this retires

| Site | Today | Reconciled |
|---|---|---|
| `core_components.ex:39` | `background-color: #{c}20; color: #{c}; border: 1px solid #{c}` | `data-status`; CSS supplies `1a` fill + `40` border |
| `core_components.ex:145` | `background-color: #{fill_color}` | `data-band`; §4 |
| `escalations_live.ex:372` | `border-color: #{c}40` | `data-status` on `.escalation-card` |
| `escalations_live.ex:374` | `background: #{c}0d` | `data-status` on `.escalation-card-head` |
| `escalations_live.ex:375` | `background-color: #{c}` | `data-status` on `.escalation-dot` |
| `pipeline_dag_live.ex:287` | `background-color: #{color}` | existing `[data-legend-status]` |

## 3. Stylesheet side

One rule set per status, consuming the seven tokens. Generated by hand, seven
blocks, no repetition of a value:

```css
/* Status transport (§II). One definition per status; every representation reads it. */
[data-status="done"]      { --sc: var(--done); }
[data-status="running"]   { --sc: var(--running); }
[data-status="escalated"] { --sc: var(--escalated); }
[data-status="halted"]    { --sc: var(--halted); }
[data-status="failed"]    { --sc: var(--failed); }
[data-status="pending"]   { --sc: var(--pending); }
[data-status="blocked"]   { --sc: var(--blocked); }
```

Representations then read `--sc`, so each spec is written **once** regardless of
status *(FR-003, SC-003)*:

```css
/* Status dot (§V): 7–9px circle in the status color. */
.status-dot { width:8px; height:8px; border-radius:var(--r-dot); background:var(--sc); }

/* Chip (§V): 10px mono 600, ls .4px, pad 3px 8px, radius 5px, X / X1a / X40. */
.status-chip {
  font-family:var(--font-mono); font-size:var(--fs-eyebrow); font-weight:600;
  letter-spacing:.4px; padding:3px var(--sp-8); border-radius:var(--r-chip);
  color:var(--sc);
  background:color-mix(in srgb, var(--sc) 10%, transparent);   /* = X1a */
  border:1px solid color-mix(in srgb, var(--sc) 25%, transparent); /* = X40 */
}

/* Escalation card head wash (§II `0d`). */
.escalation-card-head { background:color-mix(in srgb, var(--sc) 5%, transparent); }
```

**On `color-mix` vs hex suffixes.** The contract states alphas as hex suffixes
(`1a`, `40`, `0d`), which cannot be concatenated onto a `var()`. `color-mix(in
srgb, …)` is the no-toolchain equivalent and is Baseline-supported. The
percentages above are the contract's suffixes converted (`1a`≈10%, `22`≈13%,
`40`≈25%, `55`≈33%, `66`≈40%, `88`≈53%, `0d`≈5%); the mapping is fixed here so
no surface invents its own. A surface MUST NOT use any percentage outside this
table. *(FR-009)*

| Contract suffix | `color-mix` percentage | Use |
|---|---|---|
| `0d` | 5% | header wash |
| `1a` | 10% | chip fill |
| `22` | 13% | active fill |
| `40` | 25% | border |
| `55` | 33% | border, selection |
| `66` | 40% | border |
| `88` | 53% | border |

## 4. Gauge band

The gauge's color is per-render computed, so it travels as a **band**, not a
color *(FR-004b, spec edge case 5)*.

```elixir
@spec gauge_band(float(), boolean()) :: :safe | :warning | :tripped
def gauge_band(_fill, true), do: :tripped
def gauge_band(fill, _tripped?) when fill >= 100.0, do: :tripped
def gauge_band(fill, _tripped?) when fill > 80.0, do: :warning
def gauge_band(_fill, _tripped?), do: :safe
```

```heex
<div class="cost-gauge" data-band={@band} role="meter" …>
  <div class="cost-gauge-reserved" style={"width: #{@fill}%;"}></div>
  <div class="cost-gauge-fill"     style={"width: #{@committed_fill}%;"}></div>
  …
</div>
```

```css
.cost-gauge[data-band="safe"]     .cost-gauge-fill { background:var(--done); }
.cost-gauge[data-band="warning"]  .cost-gauge-fill { background:var(--escalated); }
.cost-gauge[data-band="tripped"]  .cost-gauge-fill { background:var(--failed); }
.cost-gauge-reserved { background:var(--hatch-reserved); }
```

**Thresholds.** `> 80%` warning per §VII.3, replacing today's 70%. `tripped`
comes from `Ledger.tripped?` — recorded breaker state — plus the 100% ceiling,
replacing today's 90% guess. *(FR-016, FR-020)*

**Committed vs reserved.** Committed is the solid `--done`/`--escalated`/`--failed`
fill; reserved is the `--hatch-reserved` band behind it. Merging them is
prohibited: Principle IV accounts for both, so a merged gauge misreports the
breaker's headroom.

## 5. Motion

Four keyframes; each attached only where a live referent exists *(FR-015, §VI)*.

```css
@keyframes scPulse { 0%,100%{opacity:1} 50%{opacity:.35} }
@keyframes scBlink { 0%,100%{opacity:1} 50%{opacity:.15} }
@keyframes scSlide { from{transform:translateX(16px);opacity:0} to{transform:none;opacity:1} }
@keyframes scFade  { from{opacity:0} to{opacity:1} }

.status-dot[data-status="running"],
.phase-cell-active,
.dag-node[data-status="running"] .status-dot { animation:scPulse 1.3s infinite; }

.transcript-live[data-live="true"] { animation:scBlink 1.4s infinite; }
.drawer { animation:scSlide .18s ease; }
.scrim, .toast { animation:scFade .16s ease; }

@media (prefers-reduced-motion: reduce) {
  .status-dot[data-status="running"],
  .phase-cell-active,
  .dag-node[data-status="running"] .status-dot,
  .transcript-live[data-live="true"],
  .drawer, .scrim, .toast { animation: none; }
}
```

**Rules**

- `scPulse` attaches **only** at `data-status="running"` / the active pip. No
  resting, pending, blocked, or terminal element animates or glows.
- The `.status-dot[data-ok="true"]` glow (`box-shadow: 0 0 6px #34d399`) is
  removed — a resting element wearing both an elevation shadow and a status
  color.
- `scBlink`'s live referent is **an unterminated phase attempt**: the transcript
  view marks a transcript live when its attempt has no finish record. Recorded
  state, not a timer. *(FR-020)*
- Under reduced motion the active-vs-resting distinction survives on two
  treatments the contract already defines and that are present with motion
  enabled too — the `--glow-accent` ring on the active DAG node, and the current
  phase pip rendered in the status color against `--border` future pips. No new
  color, hue, or component; never status text alone. *(FR-015a)*

## 6. Acceptance

| Check | Means |
|---|---|
| No color emitted from Elixir | guard `:color_literal` over `lib/**/web/**` |
| No color-bearing inline style | guard `:inline_style_color` (allowlist: `width:` on the two gauge fills) |
| One definition per status | guard `:duplicate_status_value` |
| Only the seven contract statuses rendered | guard `:unknown_status_selector`; `never_started → blocked` covered by a unit test |
| Only tabled alpha percentages | guard `:illegal_alpha_suffix` |
| Exactly four keyframes, all reduced-motion-stoppable | guard `:unknown_keyframe`, `:unstoppable_keyframe` |
| `scPulse` only on a live referent | guard `:animation_without_referent` (selector must contain `running` or `active`) |
| Reduced-motion static markers readable | inventory verdict (`§VI`, mission control + DAG) |
